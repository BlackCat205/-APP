# 推荐 UI 重构

首页推荐卡现在只展示一个组合、首句原因和操作入口。没有可靠数据时使用“开始认识你的气味 / 探索建议”，不显示空分数；至少存在可归属反馈且有效证据达到 2 后，显示“为你推荐”和一个综合推荐度。

“换一个”只轮换本地已经计算的候选，不访问网络。“查看更多推荐”进入候选列表，“为什么推荐”进入详情页；行为分项、AI 匹配度、置信度、完整原因及数据依据均在详情页展示。

“开始使用”仍遵循：校验当前气味配置和连接状态、用户确认、记录使用前状态、`UsageSessionService`、BLE、ESP32。多路组合由会话服务串行启动；任一路失败时尝试全部关闭，并将已经开始的部分记为中断，不能形成正常完成记录。推荐组件本身不调用 BLE。

个人中心新增“我的气味画像”。页面只读取 SQLite，展示可靠使用次数、累计时长、常用组合、最近喜欢程度变化、`preference_profiles` 中的偏好标签与当前 AI 分析状态。没有 AI 结果时不推测语义标签。断网不会影响画像中的行为统计、推荐计算或硬件控制。

## 推荐评分模拟

首页原“测试气味瞬间”入口会为当前用户生成一条 65 秒的三路模拟会话，来源明确保存为 `recommendation_simulation`，不发送 BLE。会话结束后进入正式反馈表单；提交的状态变化、喜欢程度和再次使用意愿会触发本地重新评分，并进入气味画像统计。

推荐引擎只额外接受 `recommendation_simulation`。旧的通用 `test` 记录、测试关怀和没有会话关联的记录仍被排除，避免其他界面测试意外影响推荐。

## AI 偏好更新与融合

提交或修改反馈后，`preference_profiles.input_version` 增加并进入 `pending`。首页先读取 SQLite 中的行为推荐，然后异步复用现有星火接口分析最近最多 30 条有效反馈。请求只包含气味组合、场景、前后状态、喜欢程度、再次使用意愿和一句话感受，不包含用户账号字段。

AI 必须返回 `preferred_traits`、`disliked_traits`、当前全部候选的 `candidate_scores`、`confidence` 和 `reason`。程序校验 JSON 类型、标签长度、候选 ID、候选完整性、0～100 分数、0～1 置信度及 `input_version`；任一不合法或反馈在请求期间更新，都不覆盖 SQLite 画像。失败后行为推荐继续工作，并在冷却时间后重试。

同时存在行为分和 AI 分时，行为权重为：

`有效行为证据 / (有效行为证据 + AI confidence × 3)`

综合分按行为权重和剩余 AI 权重融合。因此数据少时更依赖 AI，可靠行为证据积累后逐步转向真实行为。只有一个分数可用时直接使用该分数。
