# 第三阶段：离线行为推荐

本阶段在现有 SQLite、使用会话和反馈流程上增加独立推荐服务及首页“今日推荐”。不新增数据库版本，不调用 AI，也不从推荐卡片发送 BLE 指令。整体目标的准确表述仍是“行为反馈 + 大模型语义理解的混合式个性化推荐”；本阶段仅完成其中的行为部分。

## 服务职责

- `ScentCatalog` 为现有气味定义稳定 ID，从当前四路配置枚举最多 15 个非空组合；同气味集合去重，但保留重复气味数量。更换风扇通道不会改变气味组合身份。
- `RecommendationService` 在一次 SQLite 事务中读取当前用户的会话、反馈和使用记录，重建实际同时开启的组合区间，交给评分服务。
- `BehaviorScoringService` 是不依赖数据库、网络、BLE 或 UI 的纯 Dart 评分器，参数集中在 `BehaviorScoringConfig`。
- `RecommendationProvider` 监听会话提交、反馈保存、用户切换、气味配置及使用记录删除。异步结果带代次校验，防止旧用户或旧配置结果覆盖新结果。
- `TodayRecommendationCard` 展示已验证与探索建议、分数和原因；可展开其他候选及评分分项。

## 默认评分规则

| 信号 | 默认权重 | 转换 |
| --- | --- | --- |
| 喜欢程度 | 40% | 1～5 分转换为 0～100 |
| 前后状态变化 | 30% | `50 + 12.5 × (使用后状态 - 使用前状态)` |
| 再次使用意愿 | 20% | 0、1、2 转换为 0、50、100 |
| 使用次数与时长 | 10% | 中性基准 50，次数及平均时长各最多增加 25 |

状态量表按数值越高状态越好解释。缺失维度保持空值，按可用权重重新归一化，不填零。事后回忆的使用前状态降低该维度及证据的权重至一半；来源不明的前状态不计入变化分。

每条记录按 `0.5^(距今天数/30)` 衰减。次数信号在衰减后累计 5 次封顶，每次时长在 600 秒封顶；少用或短用本身不视为不喜欢。按会话 ID 去重，不能通过同一会话多个片段重复累计次数。

有效证据 n 来自衰减后的反馈覆盖率、可用反馈维度完整度，以及最多 0.5 的使用行为证据。原始加权分再作小样本修正：`50 + (原始分 - 50) × n/(n+2)`。默认参数下，仅有次数和时长而没有反馈时，得分最高 60。此分数是可解释的规则评分，不是成功概率或医疗效果指标。

## 数据归属与排除

只使用当前用户来源为 `app_command_unverified`、正常完成且时间与时长一致的记录。该来源表示 APP 命令流程有记录，不代表 ESP32 已提供物理执行回执。排除旧来源不明数据、测试记录、中断、执行不确定、定时估算、未来时间、损坏数据及无法完整验证的会话。

逐条比对会话保存的气味快照；若组合的一路被删除或改写，整次会话不再用于评分，防止原组合反馈错误归给剩余气味。分别使用 A 和 B 不等于使用过 A+B。

一次反馈最多归属一个主组合：该组合覆盖至少 90% 会话时间，且其他组合的过渡时间合计不超过 10 秒。其他片段只贡献使用行为，不能继承整次反馈。频繁切换、没有主组合的会话不向任何片段分配整体反馈。

## 首页与降级行为

有可靠使用记录的组合显示“已验证推荐”；尚无记录的组合显示“探索推荐”，不编造分数。本阶段探索建议只来自当前装载气味，尚未由 AI 个性化。首页优先各显示一个已验证和探索候选，其余可展开。

当前综合推荐度等于行为适配度，AI 偏好匹配度明确显示“未分析”。冷启动没有行为分时显示暂无数据。反馈保存后会自动重新评分，修改反馈可改变排序与原因。SQLite 读取失败显示可重试错误，不显示其他用户的旧结果。时间衰减在加载、数据变更或手动刷新时重新计算。

## 验证和后续边界

本阶段完成后的全套 Flutter 测试共 50 项通过，覆盖迁移、使用/反馈流程、行为公式、组合归属、配置变更、删除记录、用户隔离、异步刷新及卡片展示。测试采用临时数据库和模拟 BLE，未连接真实 ESP32。

下一阶段接入现有 AI 接口的结构化偏好解析、JSON 校验、缓存与动态融合；之后完善偏好画像、独立解释页面及“程序校验 → 用户确认 → BLE”推荐执行流程。
